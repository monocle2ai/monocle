Falls back to session-based retrieval when the deployed agent does not return them
- fix!: an agent deployed to AWS Bedrock AgentCore now authorizes each caller before returning its spans, the same gate every HTTP framework applies — the deployment declares a key in `MONOCLE_TRACE_RETRIEVAL_DEFAULT_KEY` (or a callback in `MONOCLE_TRACE_RETRIEVAL_CALLBACK`), and the `agentcore` runner presents `MONOCLE_TRACE_RETRIEVAL_KEY` on the invocation. ## Version 0.8.15 (2026-09-11)

- fix(instrumentation): a streaming inference whose consumer stops reading early now emits a span — the tokens it spent were previously unreported. `close()`/`aclose()` on the stream is the only deterministic end signal, since Python leaves an abandoned generator to the garbage collector, so both the in-place patch path and the fallback wrapper classes emit there, guarded so a `close()` after full consumption cannot produce a second span ([#818](https://github.com/monocle2ai/monocle/pull/818))
- fix(test_tools): an Okahu endpoint environment variable that is set but empty falls back to the default endpoint instead of building a scheme-less URL. `os.getenv(name, DEFAULT)` only applies its default when the name is absent, and an undefined CI variable expands to `""`, so requests raised "No scheme supplied" on `/v1/eval/templates`; `OKAHU_API_KEY` is likewise no longer `.strip()`ped unguarded when unset ([#817](https://github.com/monocle2ai/monocle/pull/817))
- fix(test_tools): remote trace retrieval waits up to `MONOCLE_REMOTE_TRACE_ID_TIMEOUT` seconds (default 60) for the agent's spans to reach the backend, instead of a hard-coded 10s that was under the time an out-of-process export takes ([#817](https://github.com/monocle2ai/monocle/pull/817))
- fix(test_tools): a failing test now reports its own error. `post_test_cleanup` already stops the scope token, but both wrappers stopped it a second time, and the double detach raised `RuntimeError: <Token ...> has already been used once` from the `finally` block while the real exception was propagating ([#814](https://github.com/monocle2ai/monocle/pull/814))
- fix(test_tools): `@pytest.mark.xfail` applies to fluent assertions. They record rather than raise, so the outcome is flipped to failed after pytest's own xfail hookwrapper has already seen a passing call — intentional-failure tests reported as hard failures, and a test that silently stopped failing was masked as a pass ([#814](https://github.com/monocle2ai/monocle/pull/814))
- fix(instrumentation): `reset_span_processors` re-appends the trace-return processor the way `setup_monocle_telemetry` does; rebuilding the processor list on an initialised instrumentor silently dropped trace return for the rest of the process ([#814](https://github.com/monocle2ai/monocle/pull/814))
- fix(test_tools): the llamaindex runner passes `memory=` only to callables that accept it, and binds it with `functools.partial` for `run_in_executor`, which takes no kwargs ([#814](https://github.com/monocle2ai/monocle/pull/814))
- feat(test_tools): the Okahu enumerators walk every page instead of stopping at the server's first page of 100, so a fact past the first page becomes a test case rather than being silently absent. `page_size` is bounds-checked locally rather than reaching the wire as an opaque HTTP 400, and a short collection warns against the advertised `fact_count` rather than raising, since discovery runs at collection time ([#813](https://github.com/monocle2ai/monocle/pull/813))
- feat(test_tools): `setup_test_cases` refuses a discovery window holding more than `max_facts` facts (argument, then `OKAHU_MAX_FACTS`, then 1000) — paginating the enumerators removed the accidental ceiling the 100-fact page used to impose, and an unbounded window is minutes of collection time and a large token bill. It refuses rather than truncating, since a silent subset is the defect pagination set out to remove ([#813](https://github.com/monocle2ai/monocle/pull/813))
- feat(test_tools): the Okahu API timeout is 120s and overridable by `OKAHU_API_TIMEOUT`; precedence is explicit argument, then the variable, then the default. An unusable value is logged and ignored rather than stopping span loading ([#810](https://github.com/monocle2ai/monocle/pull/810))
- feat(test_tools): a fact whose spans will not load is emitted carrying the reason in `FluentTestCase.load_error` and appears as one failing test under its own id, instead of costing every other fact in the window its test. A fact that loaded fine but carries no label for the requested eval is still dropped and logged, since nothing failed ([#810](https://github.com/monocle2ai/monocle/pull/810))
- fix(test_tools): a test case whose eval name is a path-like *string* is classified as a custom template, the same way `check_eval` classifies its own `eval_name`. Only `pathlib.Path` was recognized, so the eval service was asked for a built-in template called `./evals/my_eval.json` — the common case, since a test case usually arrives as JSON, which has no `Path` type ([#810](https://github.com/monocle2ai/monocle/pull/810))
- fix(instrumentation): the root path `/` can now be configured as a health check route via `MONOCLE_HEALTH_CHECK_ROUTES`. Trailing-slash stripping collapsed `/` to an empty string, so it was dropped from the route list and never matched — a health check on `/` that answered with a body was exported as real traffic on every request. `/` is not a default, since apps often serve real traffic there; opting in matches the root exactly and confirms it against the request url, so a sub app mounted at `/api` (which reports its own root endpoint as route `/`) is unaffected ([#811](https://github.com/monocle2ai/monocle/pull/811))
- feat(test_tools): add a `foundry` runner to invoke an agent already deployed to Azure AI Foundry and pull its spans back from Okahu, so existing assertions apply to a remote agent — the Foundry counterpart to the `agentcore` runner. `root_agent` is the agent's Responses URL; it authenticates with an Entra bearer token via `DefaultAzureCredential`, so `az login` and CI workload identity both work unchanged, and correlates spans by the trace id Foundry returns in `x-request-id`. Retrieval needs the workflow name the agent exports under (`trace_workflow_name` or `FOUNDRY_TRACE_WORKFLOW`); without it only the response is asserted on ([#809](https://github.com/monocle2ai/monocle/pull/809))
- fix(instrumentation): the MS Agent Framework turn span records the prompt text instead of `<agent_framework._types.Message object at 0x...>`. It read `content`, which agent-framework 1.6.0 renamed to `contents`, so the guard missed and `str()` ran on a class with no `__str__`; the remaining fallback now refuses to export an object repr ([#809](https://github.com/monocle2ai/monocle/pull/809))
- feat(test_tools): parametric tests — a recorded population becomes a parametrizable list of test cases, for eval tuning and A/B testing. `setup_test_cases()` builds one `FluentTestCase` per fact from the evals already recorded in Okahu (or from a committed JSON array with `source="local"`, so a discovered set can be dumped and reloaded as a golden dataset with no network call), and `testcase=` is accepted by `with_trace_source`, `run_agent`/`run_agent_async`, `check_eval`, `called_agent`, `called_tool` and the input/output assertions. Every eval a case names is graded and all failures reported together, `compare_eval` borrows the expected result from a different eval, the trace sources take a `start_time`/`end_time` window, and parametrized cases are named after the case rather than `[testcase0]`. See [test_tools/README.md](test_tools/README.md) ([#806](https://github.com/monocle2ai/monocle/pull/806))
- feat(instrumentation): an MS Agent Framework agent using Azure AI Foundry produces a complete trace, identifies Foundry as its host, and its spans can be read back from Okahu. Previously the same run reported `app_hosting.generic`, carried an empty `data.output` on every inference span with no `span.subtype`, and could not be retrieved from Okahu at all — `FOUNDRY_PROJECT_ENDPOINT` was not a recognized marker, the hosting name resolved to generic, openai's raw-response wrapper was unwrapped to the HTTP response rather than through `parse()`, and the span loader queried `/api/v1/workflows`, which no longer exists ([#804](https://github.com/monocle2ai/monocle/pull/804))
